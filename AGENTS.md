# Правила работы Codex

## Общие правила

- Следуй текущему этапу из [`PLANS.md`](PLANS.md). Не переходи к следующему этапу без подтверждения пользователя.
- Сохраняй модульность: интерфейс, backend, библиотека документов и каждый агент имеют отдельные границы.
- До реализации не устанавливай зависимости и не подключай платные или внешние сервисы.
- Не публикуй, не копируй в репозиторий и не передавай в Codex Cloud реальные пользовательские документы, их фрагменты, метаданные, базу, журналы или резервные копии.
- Не запрашивай и не используй реальные API-ключи. Для разработки допустимы только явно фиктивные примеры.
- Не совершай действия с реальными письмами. Агент переписки готовит файлы и не отправляет сообщения.

## Обращение с файлами и данными

- Оригиналы документов неизменяемы: анализ и будущие результаты создаются отдельно.
- Храни пользовательские данные вне каталога установки, в профиле текущего пользователя Windows. Не добавляй рабочие данные в Git.
- Все операции с путями строй по внутреннему идентификатору и проверяй, что итоговый путь находится внутри разрешённого каталога.
- Проверяй размер, расширение и содержимое загружаемого файла. Не запускай макросы, вложенный код, скрипты и активное содержимое.
- Опасные или необратимые действия, включая восстановление резервной копии, требуют явного подтверждения.
- Backend привязывай только к `127.0.0.1`; защита должна включать проверку источника запроса и непредсказуемый токен сессии, а не только loopback-привязку.
- Перед любой будущей передачей данных внешнему ИИ покажи цель, конкретные выбранные файлы/данные и объём передачи; начинай передачу только после отдельного согласия пользователя.

## Изменения и проверка

- Сначала изучи существующую структуру и локальные инструкции. Вноси небольшие, обозримые изменения.
- Не меняй формат базы, пути хранения или API без обновления соответствующей документации.
- Добавляй в Git только исходный код, документацию, тесты и обезличенные фикстуры. Проверяй `.gitignore` перед добавлением файлов.
- Не утверждай, что сборка или проверка пройдена, если она не запускалась.
- В итоговом сообщении перечисляй изменения, выполненные проверки и известные ограничения.

# План реализации Office AI

Работы идут последовательно небольшими этапами. Перед началом каждого следующего этапа требуется подтверждение пользователя.

1. **Проектирование** (завершён): назначение, архитектура, модель данных, безопасность, критерии MVP, Windows-сборка и правила Codex.
2. **Каркас приложения** (завершён): минимальная структура React/TypeScript, FastAPI, pywebview, запуск в режиме разработки и разделение модулей. Без ИИ и без доступа к внешним сервисам.
3. **Локальное хранилище и настройки** (завершён): каталог данных пользователя, миграции SQLite, настройки и журнал операций.
4. **Библиотека документов** (завершён): загрузка, проверка типов и размеров, SHA-256, обнаружение дубликатов, поиск, фильтрация, сортировка, скачивание и безопасные пути.
5. **Резервирование и восстановление** (завершён): локальная резервная копия и проверяемое восстановление с подтверждением пользователя.
6. **Интерфейс MVP и экраны агентов** (завершён): главная, навигация, библиотека, настройки и четыре подготовленных самостоятельных экрана агентов без ИИ-вызовов.
7. **Проверки и приёмка MVP** (автоматическая часть завершена; ручная приёмка частично выполнена): автоматизированные проверки и сценарии безопасности согласно [`docs/acceptance.md`](docs/acceptance.md). Пользователь подтвердил запуск установленной программы; прочие ручные сценарии приёмки пока не закрыты.
8. **Windows-сборка** (автоматическая проверка завершена): GitHub Actions run 20 на Windows Server 2022 собрал приложение, выполнил тихую установку/удаление и проверил создание WebView2 окна с загрузкой интерфейса. Пользователь подтвердил успешный запуск установленной программы. Проверку на других версиях Windows следует выполнить отдельно.
9. **Агенты и внешние модели** (локальная подготовка данных): добавлены одноразовый шлюз согласия, allow-list задач и предпросмотр выбранных DOCX/XLSX/PPTX. Синтетические проверки подтверждают чтение без изменения оригинала, пропуск формул, порядок слайдов, отклонение XML-сущностей и неподдерживаемого PDF. Следующий подэтап — ручная проверка интерфейса на Windows с обезличенными синтетическими файлами и согласование правил передачи/фрагментов. Подключение provider adapter и внешней модели требует отдельного согласования.

Этапы 5 и 6 завершены. Автоматические проверки этапа 7 выполнены. Windows CI run 20 успешно проверил GUI smoke; пользователь подтвердил, что приложение открывается. Этап 9 остаётся полностью локальным: согласие, каталог задач и предпросмотр DOCX/XLSX/PPTX работают без внешней передачи; backend synthetic suite проходит. До подключения провайдера ещё нужно вручную проверить экран агента в установленной Windows-сборке и согласовать поставщика, модель, формат фрагментов и обработку данных. Полная приёмка MVP ещё не завершена.

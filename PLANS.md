# План реализации Office AI

Работы идут последовательно небольшими этапами. Перед началом каждого следующего этапа требуется подтверждение пользователя.

1. **Проектирование** (текущий этап): назначение, архитектура, модель данных, безопасность, критерии MVP, Windows-сборка и правила Codex. Результат — проверяемая документация; приложения пока нет.
2. **Каркас приложения**: минимальная структура React/TypeScript, FastAPI, pywebview, запуск в режиме разработки и разделение модулей. Без ИИ и без доступа к внешним сервисам.
3. **Локальное хранилище и настройки**: каталог данных пользователя, миграции SQLite, настройки и журнал операций.
4. **Библиотека документов**: загрузка, проверка типов и размеров, SHA-256, обнаружение дубликатов, поиск, фильтрация, сортировка, скачивание и безопасные пути.
5. **Резервирование и восстановление**: локальная резервная копия и проверяемое восстановление с подтверждением пользователя.
6. **Интерфейс MVP и экраны агентов**: главная, навигация, библиотека, настройки и четыре подготовленных экрана агентов без ИИ-вызовов.
7. **Проверки и приёмка MVP**: автоматизированные проверки, ручные сценарии, проверка изоляции данных и локального API согласно [`docs/acceptance.md`](docs/acceptance.md).
8. **Windows-сборка**: настройка GitHub Actions на Windows runner, PyInstaller и Inno Setup; проверка чистой установки на Windows 10/11 согласно [`docs/windows-build.md`](docs/windows-build.md).
9. **Агенты и внешние модели** (отдельный будущий этап): спецификация задач, согласие на конкретную передачу, безопасное хранение ключей и интеграция OpenAI Agents SDK. Требует отдельного согласования объёма и политики передачи.

Этапы 2–8 не включены в текущую задачу. Этот план сам по себе не является разрешением начинать их.

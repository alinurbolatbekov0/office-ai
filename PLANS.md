# План реализации Office AI

Работы идут последовательно небольшими этапами; завершение очередного этапа фиксируется здесь и в проверках.

1. **Проектирование** (завершён): назначение, архитектура, модель данных, безопасность, критерии MVP, Windows-сборка и правила Codex.
2. **Каркас приложения** (завершён): минимальная структура React/TypeScript, FastAPI, pywebview, запуск в режиме разработки и разделение модулей. Без ИИ и без доступа к внешним сервисам.
3. **Локальное хранилище и настройки** (завершён): каталог данных пользователя, миграции SQLite, настройки и журнал операций.
4. **Библиотека документов** (завершён): загрузка, проверка типов и размеров, SHA-256, обнаружение дубликатов, поиск, фильтрация, сортировка, скачивание и безопасные пути.
5. **Резервирование и восстановление** (завершён): локальная резервная копия и проверяемое восстановление с подтверждением пользователя.
6. **Интерфейс MVP и экраны агентов** (завершён): главная, навигация, библиотека, настройки и четыре подготовленных самостоятельных экрана агентов без ИИ-вызовов.
7. **Проверки и приёмка MVP** (автоматическая часть завершена; ручная приёмка частично выполнена): автоматизированные проверки и сценарии безопасности согласно [`docs/acceptance.md`](docs/acceptance.md). Пользователь подтвердил запуск установленной программы; прочие ручные сценарии приёмки пока не закрыты.
8. **Windows-сборка** (автоматическая проверка завершена): GitHub Actions run 20 на Windows Server 2022 собрал приложение, выполнил тихую установку/удаление и проверил создание WebView2 окна с загрузкой интерфейса. Пользователь подтвердил успешный запуск установленной программы. Проверку на других версиях Windows следует выполнить отдельно.
9. **Локальный рабочий процесс агентов** (готово для синтетических данных): отдельные каталоги задач, локальный предпросмотр DOCX/PDF/XLSX/PPTX, поиск с пагинацией и минимальная история. OCR для сканов/изображений не входит в текущий объём.
10. **Подтверждаемое подключение OpenAI** (код и mock-проверки готовы): ключ сохраняется в Windows Credential Manager, до отправки показывается точный JSON body, одноразовое подтверждение необходимо для каждой передачи, отмена не обращается к сети, результат хранится в SQLite отдельно от оригиналов. Адаптер использует фиксированный HTTPS endpoint без редиректов и автоматических повторов. Agents SDK отложен: узкий HTTP-адаптер проще проверить на соблюдение границы данных.
11. **Финальная проверка установленной сборки** (не завершена): подтвердить на Windows 10/11 новую Actions-сборку и рабочий Credential Manager. Пользователь должен сам настроить ключ, проверить disclosure с синтетическим файлом и подтвердить или отменить; реальные конфиденциальные документы для проверки не использовать. Реальный запрос требует пользовательского разрешения непосредственно в приложении и может тарифицироваться.

Windows package run 58 проверил установку/запуск/удаление предыдущей версии; пользователь подтвердил запуск. Текущий код провайдера добавлен после этой сборки, поэтому перед эксплуатацией нужно проверить новый артефакт на Windows. Разработка и тесты использовали только синтетические данные и заглушку, сетевой запрос OpenAI не отправлялся. Сканированные документы и изображения пока не поддерживаются.

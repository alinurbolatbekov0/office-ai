# Модель локальной базы данных

SQLite — локальная база одного пользователя: настройки, журнал, метаданные библиотеки и история будущих задач. На Windows база располагается в `%LOCALAPPDATA%\OfficeAI\officeai.sqlite3`; оригиналы файлов — в `%LOCALAPPDATA%\OfficeAI\documents\`. В тестах путь задаётся явно. Версия схемы хранится через `PRAGMA user_version` и таблицу `schema_migrations`. Пользовательские данные не коммитятся в Git.

## Реализованная схема версии 3

Приложение последовательно применяет миграции 1, 2 и 3, сохраняя настройки и журнал существующей базы версии 1 и библиотеки из версии 2.

### `schema_migrations`

| Поле | Назначение |
|---|---|
| `version` | Номер применённой миграции, первичный ключ |
| `applied_at` | Время применения, UTC |

### `app_settings`

| Поле | Назначение |
|---|---|
| `setting_key` | Ключ из разрешённого набора, первичный ключ |
| `value_json` | Типизированное JSON-значение |
| `updated_at` | Время изменения, UTC |

Начальные настройки: `theme` (`light`/`dark`) и `confirm_destructive_actions` (boolean, по умолчанию `true`). Неизвестные ключи и значения отклоняются. Секреты в эту таблицу не помещаются.

### `operation_log`

| Поле | Назначение |
|---|---|
| `id` | UUID операции, первичный ключ |
| `occurred_at` | Время UTC |
| `operation_code` | Код операции из закрытого набора |
| `outcome` | `success` или `failure` |
| `entity_type` / `entity_id` | Безопасная ссылка на сущность при наличии |
| `message_code` | Код локализуемого сообщения |

Журнал не принимает произвольный текст, исходное имя файла, содержимое файла или значения настроек. Он фиксирует запуск, сохранение настройки, успешную загрузку, обнаружение дубля и отклонённую загрузку кодами из закрытого набора. API возвращает не более 100 последних строк; UI показывает до 20.

## Основные сущности

### `stored_files`

Одна запись на уникальное содержимое файла. SHA-256 задан как `UNIQUE`; повторное добавление содержимого не создаёт ещё одну копию байтов.

| Поле | Назначение |
|---|---|
| `id` | Случайный внутренний UUID, первичный ключ |
| `sha256` | Хеш сохранённых байтов, уникальный индекс для определения дублей |
| `storage_key` | Сгенерированный приложением относительный ключ хранения; не путь от пользователя |
| `size_bytes` | Размер файла |
| `detected_type` | Один из разрешённых типов: DOCX, XLSX, PPTX, PDF, JPEG, PNG; проверен по сигнатуре/структуре |
| `created_at` | Время первого добавления, UTC |

### `documents`

Элементы библиотеки, отображаемые пользователю. Это позволяет хранить несколько исходных имён для одинакового содержимого, не сохраняя несколько копий байтов.

| Поле | Назначение |
|---|---|
| `id` | Случайный UUID, первичный ключ |
| `stored_file_id` | Внешний ключ на `stored_files` |
| `original_name` | Исходное Unicode-имя только как метаданные, без пути |
| `extension` | Проверенное расширение |
| `imported_at` | Время импорта, UTC |

### `agent_task_history`

Локальная история успешной подготовки предпросмотра. Она содержит только внутренний UUID записи, код агента и задачи, фиксированный исход `preview_ready`, число источников и время. Содержимое, инструкции пользователя, имена файлов, пути, извлечённый текст и результаты в этой таблице не сохраняются. Это не история ответов ИИ: внешняя модель пока отключена.

При повторном импорте API сообщает о совпадении и возвращает существующие записи. Пользователь может отменить импорт либо явно подтвердить создание ещё одной записи, связанной с теми же сохранёнными байтами. Повторная загрузка не перезаписывает оригинал.

### `settings` (обобщённое название для будущих версий)

Текущая таблица называется `app_settings`. API-ключи в SQLite не хранятся; для будущей интеграции нужен Windows Credential Manager или другой системный защищённый контейнер секретов.

Будущая история полноценных задач ИИ должна моделироваться отдельно: не добавлять исходный текст/результаты в минимальную `agent_task_history` без отдельного решения по срокам хранения, просмотру и удалению.

## Связи

```text
stored_files 1 ─── * documents
documents    1 ─── * operation_log (логическая ссылка по entity ID)
```

`agent_task_history` является отдельным локальным списком; операции предпросмотра также отражаются в `operation_log` только фиксированным кодом, без текста.

Для связи журнала с несколькими типами сущностей используется `entity_type` + `entity_id` без полиморфного внешнего ключа. Сейчас созданы индексы `operation_log_occurred_at_idx`, `documents_imported_at_idx` и `documents_stored_file_idx`; поиск по имени использует Unicode casefold в SQLite. `stored_files.sha256` уникален.

## Ограничения целостности и транзакции

- Внешние ключи включены при каждом подключении (`PRAGMA foreign_keys=ON`).
- Импорт принимает поток байтов с пределом 100 МиБ, записывает его во временный файл внутри пользовательского хранилища и считает SHA-256. После проверки типа оригинал атомарно закрепляется под случайным внутренним именем; метаданные фиксируются SQLite-транзакцией. При ошибке временная копия удаляется. Файл не распаковывается и не исполняется.
- Для атомарной записи создаётся hard link в пределах одного локального хранилища, затем временное имя удаляется.
- Не удалять физическое содержимое, пока есть связанные библиотечные записи. Правила удаления/корзины требуют отдельного решения.
- Резервная копия включает согласованный SQLite snapshot через встроенный backup API и все оригиналы из `stored_files`. Архив ZIP содержит манифест версии 1 со списком внутренних путей, размеров и SHA-256. До восстановления файл проходит полную проверку в staging-каталоге: структура архива, список файлов, контрольные суммы, целостность SQLite, версия схемы и соответствие строк `stored_files` содержимому.
- Восстановление выполняется после явного подтверждения. Перед заменой SQLite и `documents/` текущие элементы перемещаются в rollback-каталог; при ошибке замены прежние данные возвращаются. После успеха создаётся запись `backup_restored` в восстановленном журнале. Резервные копии и временные каталоги находятся в `backups/`, отдельно от приложения.
- Даты — UTC в согласованном ISO-8601 формате. Размеры — целые байты; идентификаторы не раскрывают путь.

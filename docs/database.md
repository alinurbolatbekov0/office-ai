# Модель локальной базы данных

SQLite — локальная база одного пользователя. Она хранит метаданные и историю, но не заменяет файловое хранилище оригиналов. Все таблицы и миграции обслуживаются приложением; пользовательские данные не коммитятся в Git.

## Основные сущности

### `stored_files`

Одна запись на уникальное содержимое файла.

| Поле | Назначение |
|---|---|
| `id` | Случайный внутренний UUID, первичный ключ |
| `sha256` | Хеш сохранённых байтов, уникальный индекс для определения дублей |
| `storage_key` | Сгенерированный приложением относительный ключ хранения; не путь от пользователя |
| `size_bytes` | Размер файла |
| `detected_type` | Один из разрешённых типов: DOCX, XLSX, PPTX, PDF, JPEG, PNG |
| `created_at` | Время первого добавления, UTC |

### `documents`

Элементы библиотеки, отображаемые пользователю. Это позволяет хранить несколько исходных имён для одинакового содержимого, не сохраняя несколько копий байтов.

| Поле | Назначение |
|---|---|
| `id` | Случайный UUID, первичный ключ |
| `stored_file_id` | Внешний ключ на `stored_files` |
| `original_name` | Исходное Unicode-имя только как метаданные, без пути |
| `extension` | Проверенное расширение |
| `imported_at` | Время импорта, UTC |

Решение о повторном импорте дубля: показывать предупреждение и предлагать отмену либо добавить библиотечную запись, связанную с уже сохранёнными байтами. Автоматически перезаписывать оригинал нельзя. UI-поведение необходимо закрепить до реализации библиотеки.

### `operation_log`

Журнал событий: UUID, время UTC, код операции, результат, внутренний ID сущности при наличии и безопасные дополнительные метаданные. Не хранит содержимое, текст документа, ключи или токены. Нужно определить срок хранения и поведение очистки до реализации.

### `settings`

Настройки приложения в форме ключ/значение с типизированной сериализацией и отметкой времени изменения. Не использовать эту таблицу для секретов. API-ключи в MVP не предусмотрены; для будущей интеграции нужен системный Windows Credential Manager или другой одобренный OS secret store.

### `agent_tasks` (схема для локальной истории)

Каркас истории задач с UUID, типом агента, состоянием, временем создания/завершения и ссылкой на результат. В MVP записи не создаются, потому что ИИ и выполнение задач отключены. Будущая схема должна хранить локальные входы/выходы с контролем доступа и отдельными правилами удаления; передача модели не подразумевается наличием записи.

## Связи

```text
stored_files 1 ─── * documents
documents    1 ─── * operation_log (логическая ссылка по entity ID)
agent_tasks  1 ─── * operation_log (логическая ссылка по entity ID)
```

Для связи журнала с несколькими типами сущностей можно использовать `entity_type` + `entity_id` без полиморфного внешнего ключа. Индексы: уникальный `stored_files.sha256`, `documents.imported_at`, поиск по `documents.original_name` и `agent_tasks.created_at`.

## Ограничения целостности и транзакции

- Внешние ключи включены при каждом подключении (`PRAGMA foreign_keys=ON`).
- Импорт: сначала временный файл в том же хранилище, проверка размера/хеша/типа, затем атомарное перемещение; метаданные фиксируются транзакционно. При сбое временный файл удаляется, а неполные записи не остаются.
- Не удалять физическое содержимое, пока есть связанные библиотечные записи. Правила удаления/корзины требуют отдельного решения.
- Резервирование выполняется согласованным SQLite backup API плюс копирование нужных оригиналов и манифеста. Восстановление проверяет манифест, хеши и границы путей до замены данных.
- Даты — UTC в согласованном ISO-8601 формате. Размеры — целые байты; идентификаторы не раскрывают путь.

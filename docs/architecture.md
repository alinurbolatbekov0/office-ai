# Архитектура Office AI

## Цели и ограничения

Приложение обслуживает одного локального пользователя на Windows 10/11. Сеть не нужна для библиотеки, истории, настроек и резервирования. На этапе MVP агенты показывают подготовленные интерфейсы, но не анализируют документы и не вызывают ИИ. Интерфейс программы — русский; Unicode-имена и документы на русском и казахском поддерживаются без транслитерации.

## Компоненты

```text
React + TypeScript (SPA)
        │ локальный API / ограниченный native bridge
pywebview — окно приложения
        │ запускает и останавливает
FastAPI (127.0.0.1, loopback-only)
        │
Application services ── Domain modules
        │                 ├─ Document Library
        │                 ├─ Agent: Документооборот
        │                 ├─ Agent: Деловая переписка
        │                 ├─ Agent: Excel-аналитика
        │                 └─ Agent: Презентации
        ├─ SQLite persistence adapter
        └─ Local document storage (generated names, immutable originals)
```

UI вызывает прикладные сервисы через версионируемый API. Сервисы координируют сценарии; доменные модули не знают о React, SQLite и расположении пользовательского профиля. SQLite находится на внешнем краю и предоставляет миграции, настройки, журнал и метаданные библиотеки. Файловый адаптер хранит байты оригиналов под сгенерированными именами. Агентам в будущем выдаются ограниченные сервисы/возможности, а не произвольный доступ к файловой системе или базе.

## Независимые агенты

У каждого агента собственный модуль, тип задач, входная схема и представление результата. Общие части — библиотека документов, согласие на передачу данных и журнал — предоставляются сервисами платформы. Модули не вызывают друг друга напрямую. Позже совместные сценарии сможет координировать отдельный workflow/orchestrator, который явно задаёт входы, выходы, разрешения и журналируемые переходы.

В MVP модули содержат только контракты и интерфейсные состояния. OpenAI Agents SDK не входит в исполняемый путь и не требуется для сборки MVP. Будущий адаптер ИИ должен быть отдельным модулем и получать только подтверждённый пользователем набор данных.

Для следующего этапа добавлены типизированное раскрытие передачи (`TransferManifest`) и прикладной шлюз одноразового согласия (`AgentTransferConsent`). Эти компоненты остаются вне сети и SQLite: будущий адаптер модели сможет получить payload только после подтверждения конкретного manifest и проверки SHA-256 тела, показанного пользователю. Подробные правила передачи описаны в [`agent-data-transfer.md`](agent-data-transfer.md).

## Desktop и локальный API

Предлагается сохранить React + TypeScript и FastAPI, а Windows-оболочкой сделать pywebview. Она позволяет запускать backend и показывать SPA в компактном нативном окне без установки пользователем Python или Node.js: runtime Python включается в пакет. Node.js понадобится только для разработки/сборки frontend на CI, но не конечному пользователю. Electron добавил бы крупный runtime и второй основной слой упаковки; Tauri потребовал бы поддерживать ещё и Rust-часть при уже необходимом Python backend.

Backend при запуске занимает свободный loopback-порт заранее созданным сокетом, привязанным только к `127.0.0.1`. Он выдаёт случайный токен на один запуск. Минимальный pywebview bridge передаёт адрес API и токен только коду интерфейса в окне приложения; токен не публикуется в HTML, URL или ответах API. Bridge также предоставляет отдельную операцию сохранения выбранной резервной копии через системный диалог: интерфейс передаёт только внутренний ID, а байты копируются потоком из локального хранилища в выбранный пользователем путь. API проверяет точный `Host`, `Origin`, токен сессии и ограниченный CORS preflight. Swagger/OpenAPI endpoints отключены. Vite в режиме разработки также слушает только `127.0.0.1`.

Свободный порт уменьшает конфликты, но сам по себе не является контролем доступа. Loopback защищает от удалённых сетевых клиентов, а проверка origin и токена — от посторонних локальных веб-страниц и CSRF. Windows Firewall не должен открывать входящий сетевой доступ. Текущий API предоставляет статус, каталог агентов, ограниченные настройки, журнал, библиотеку и резервное копирование. API-запросы сериализованы, чтобы восстановление не пересекалось с изменением настроек или загрузкой документов. ИИ-вызовы не реализованы.

## Потоки данных MVP

1. Пользователь выбирает файл через системный диалог приложения.
2. API принимает байты потоком, ограничивает размер, проверяет расширение и сигнатуру/структуру контейнера, вычисляет SHA-256.
3. Файл временно записывается в `%LOCALAPPDATA%\OfficeAI\documents\.tmp`, затем атомарно закрепляется под UUID-именем. Байты не преобразуются; исходное имя остаётся метаданными.
4. SQLite хранит метаданные и внутренний ID. Совпавший SHA-256 возвращает явный запрос подтверждения; после подтверждения новая запись ссылается на уже сохранённые байты.
5. Поиск и фильтрация выполняются над метаданными. Скачивание по внутреннему UUID проверяет разрешённый корень и возвращает оригинальные байты.
6. Резервирование создаёт SQLite snapshot и архив ZIP с оригиналами, размерами и SHA-256 в манифесте. При восстановлении все элементы сначала проверяются в staging; только после этого данные меняются с сохранением rollback-копии на время операции.
7. Журнал фиксирует коды операций без имени или содержимого документа. Агенты в MVP не читают файлы.

## Расположение локальных данных

По умолчанию: `%LOCALAPPDATA%\OfficeAI\` текущего пользователя, отдельно от установленной программы. Предлагаемое разбиение: `officeai.sqlite3`, `documents/`, `backups/`, `logs/`. Пользовательские данные не включаются в дистрибутив и обновление приложения. Возможность изменить корневой каталог — отдельное продуктовое решение; если её добавлять, валидация каталога остаётся обязательной.

В версии 2 создаётся подкаталог `documents/`, а временная область загрузки очищается после каждого запроса. Резервные архивы и временные файлы восстановления располагаются в `backups/`. Для разработки и тестов на Linux/macOS предусмотрен XDG-каталог.

## Ошибки и наблюдаемость

Пользователю показываются понятные ошибки на русском языке. Технические журналы не содержат текста документов, API-ключей, токенов и содержимого будущих запросов к ИИ. Операционный журнал SQLite фиксирует тип, время, результат и ID сущности, а не документный текст.

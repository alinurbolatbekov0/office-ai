# Защита данных и безопасные границы

## Модель угроз

Защищаем пользовательские файлы и метаданные от случайной публикации, удалённого сетевого доступа, браузерных атак на локальный API, ошибочной обработки имени/формата и небезопасного восстановления. Приложение работает на личной Windows-машине; полностью скомпрометированная учётная запись Windows находится вне этой модели.

## Локальное хранение и Git

- Размещать базу, оригиналы, результаты, историю, журналы и резервные копии под `%LOCALAPPDATA%\OfficeAI\`, а не в каталоге программы или репозитория.
- Ограничить доступ средствами ACL профиля текущего пользователя; не менять ACL на широкие разрешения.
- В Git хранить только код, документацию, тесты и специально обезличенные примеры. Не использовать реальные документы даже для демонстраций.
- Исключить из репозитория базы (`*.sqlite*`), пользовательские документы, резервные копии, логи, секреты, `.env` и каталоги сборки. Для этого в репозитории должен быть поддерживаемый `.gitignore`.
- База создаётся в `%LOCALAPPDATA%\OfficeAI\officeai.sqlite3`, оригиналы — в `%LOCALAPPDATA%\OfficeAI\documents\`; пути тестов внедряются явно. Таблица настроек принимает только перечисленные приложением ключи и допустимые значения. Операционный журнал хранит фиксированные коды, время и ID настройки/записи, но не значения настроек или содержимое документов.
- Не использовать реальные ключи в разработке, логах, CI или документации. Будущие секреты хранить в Windows Credential Manager, не в SQLite, исходниках или настройках.

## Загрузка, типы и неизменность оригиналов

- Белый список: DOCX, XLSX, PPTX, PDF, JPG/JPEG, PNG. Проверять расширение, сигнатуру/структуру контейнера и разумные ограничения размера; не доверять MIME, присланному клиентом.
- Серверный лимит загрузки — 100 МиБ на файл; UI показывает то же ограничение. Размер проверяется во время потоковой записи и по `Content-Length`, когда он предоставлен.
- Имена обрабатываются как метаданные Unicode. Не использовать имя, расширение или пользовательский путь в качестве пути записи.
- Сохранять оригинальные байты неизменёнными. Запись через случайное временное имя и атомарную операцию; чтение на скачивание не преобразует документ.
- ZIP-контейнеры Office рассматриваются как недоверенные: библиотека проверяет список записей и суммарный распакованный размер, но не извлекает файлы. Макросы, embedded scripts, OLE и активное содержимое не запускаются.
- Не включать автоматический предпросмотр/рендеринг документов в MVP. Если добавится позднее — изолированный процесс и отдельная проверка.

## Пути и локальный API

- Backend слушает строго `127.0.0.1` на динамическом локальном порту; не использовать `0.0.0.0`, сетевые интерфейсы или открывать входящее правило Firewall.
- Проверять допустимые `Host` и `Origin`, не включать wildcard CORS, использовать непредсказуемый токен сессии с минимальным сроком жизни. Не передавать токен в URL или логах.
- В каркасе backend выдаёт токен только через минимальный pywebview bridge активному приложению; нет HTTP bootstrap endpoint и токена в HTML/URL. Для локального HTTP API необходима защита от CSRF и DNS rebinding, включая точную проверку `Host`/`Origin`.
- API принимает внутренние ID вместо абсолютных или относительных путей. Любой путь из базы разрешается относительно фиксированного корня, нормализуется и проверяется, что остаётся внутри него (включая символические ссылки/точки перехода).
- Загрузка передаёт исходные байты потоком и имя в отдельном заголовке; URL и тело запроса не принимают путь к месту назначения. На диске используются UUID-имена, а исходное имя хранится только в SQLite. Скачать можно только по UUID записи библиотеки.
- Ограничивать методы, тела запросов, частоту и размеры. Отклонять неожиданную сериализацию и некорректные ID.

## Дубликаты, операции и резервные копии

- SHA-256 применяется для определения идентичности байтов, а не как единственный контроль целостности границ.
- Журнал содержит тип операции, время, результат и ID, без текста документов, секретов и токенов.
- Перед удалением, заменой данных или восстановлением показать понятное подтверждение с последствиями. До реализации продумать транзакционную/откатную схему восстановления.
- Резервная копия может содержать все документы в открытом виде. UI должен явно сообщать место назначения и чувствительность; не синхронизировать её с облаком автоматически. Вопрос шифрования резервных копий остаётся открытым.

## Будущая передача ИИ

ИИ-вызовы отключены в MVP. В будущем для каждой операции отдельно показать поставщика, цель, перечень конкретных файлов/фрагментов и категорий данных, после чего получить явное подтверждение. Не считать общее включение API или сохранённый ключ согласием на передачу. Отмена должна работать до отправки. Фиксировать факт/объём передачи без записи содержимого. Настройка поставщика и ключ не должны отправляться в Git или храниться рядом с документами.

## Опасные действия

Операции с необратимым воздействием, включая восстановление, массовое удаление или очистку журнала, требуют подтверждения и понятного описания результата. Для открытия/запуска приложением вложений показывать системный выбор пользователя; документы не исполняются приложением.

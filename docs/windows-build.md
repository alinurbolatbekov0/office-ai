# Сборка и установка Windows-приложения

## Выбранный путь

Windows-сборка выполняется в GitHub Actions на Windows runner. Пользователю поставляется установщик `.exe`; на его компьютере не нужны Python, Node.js или Git.

Предлагаемая цепочка:

1. CI использует Windows Server 2022 runner, Node.js 20.19.1 и Python 3.12.10.
2. CI устанавливает зависимости backend с закреплёнными версиями верхнего уровня и PyInstaller 6.13.0. Frontend использует `npm ci` по `package-lock.json`.
3. Frontend собирается в статические файлы, которые включаются в приложение.
4. PyInstaller собирает Python-приложение, FastAPI, pywebview, Windows engine dependencies и статические ресурсы в Windows-пакет. Для надёжного обнаружения ресурсов используется режим `onedir`; все runtime-файлы лежат рядом с exe.
5. Inno Setup 6.4.3 формирует per-user установщик `.exe` в `%LOCALAPPDATA%\Programs\Office AI`; права администратора не нужны.
6. Windows workflow выполняет тихую установку и удаление на свежем runner, проверяет файлы приложения, запуск entrypoint с `--help` и сохранность маркера пользовательских данных после удаления.
7. CI сохраняет установщик как временный workflow artifact на 14 дней. Публикация релиза не автоматизируется.

Workflow расположен в [`.github/workflows/windows-package.yml`](../.github/workflows/windows-package.yml), сценарий тихой установки — в [`packaging/smoke-installed-package.ps1`](../packaging/smoke-installed-package.ps1).

`PyInstaller --onefile` может быть рассмотрен только после проверки времени старта, временной распаковки и антивирусных ложных срабатываний. Для MVP `onedir` проще отлаживать и предсказуемо включать ресурсы.

## WebView2 и pywebview

pywebview использует системный Microsoft Edge WebView2 Runtime. Установщик его не скачивает и не включает. На Windows 11 он обычно присутствует; на части систем Windows 10 его может не быть. Если runtime отсутствует, окно программы не запустится. Перед релизом нужно выбрать: установить обязательный runtime и понятное сообщение с официальной ссылкой, включить согласованный offline/fixed runtime пакет или ограничить поддерживаемую конфигурацию. Тихая установка компонентов из сети запрещена.

## Надёжность workflow

- Указывать поддерживаемые Windows runner и фиксировать версии Python, Node.js, Inno Setup и PyInstaller. `package-lock.json` закрепляет frontend-граф; backend прямые зависимости закреплены в `backend/requirements.txt`, но полный lock транзитивных Windows wheel-пакетов пока нужен для более строгой воспроизводимости.
- Триггеры — pull request и защищённая ветка; реальные API-ключи и пользовательские данные workflow не нужны.
- Запускать проверки и сборку, затем проверять структуру пакета. Подписывать бинарные файлы можно отдельным этапом после решения о сертификате и бюджете; не хранить закрытый ключ в репозитории.
- Не создавать артефакт, включающий SQLite/файлы из каталога пользователя. Собирать только из исходников и обезличенных тестовых данных.
- Загружать `.exe` как временный артефакт Actions с ограниченным сроком хранения. Публиковать постоянный релиз только после отдельного согласования.
- Для воспроизводимости сохранять версии toolchain и хеши исходников/артефактов, где это поддерживается. Временный workflow artifact не является подписанным релизом.

## Установка и пути

- Программа устанавливается для текущего пользователя в `%LOCALAPPDATA%\Programs\Office AI`, отдельно от `%LOCALAPPDATA%\OfficeAI\`.
- Backend стартует как дочерний процесс/встроенный сервис жизненного цикла приложения, слушает только loopback и завершается при закрытии окна.
- Обновление заменяет файлы программы, но оставляет базу, документы, настройки и резервные копии нетронутыми.
- Деинсталлятор по умолчанию сохраняет пользовательские данные. Удаление данных — отдельная явно подтверждаемая опция.
- Вызовы установщика не содержат Python/Node prerequisites. WebView2 Runtime — отдельная проверка и решение, описанное выше.

## Нужны решения до релиза

1. Уточнить минимальную версию Windows 10 и вручную проверить на Windows 10 и Windows 11.
2. Решить, как сообщать/устанавливать обязательный WebView2 Runtime без скрытой сетевой загрузки.
3. Добавить полный lock транзитивных Windows-зависимостей для строгой воспроизводимости.
4. Решить вопрос цифровой подписи установщика и сертификата.
5. Определить версионирование, каналы обновления и процедуру миграций пользовательской базы.
6. Определить постоянный срок хранения и процесс публикации релизов отдельно от краткоживущего CI artifact.

# Отчёт о проверках MVP

Состояние на 21 октября 2026 года. Это результаты проверок в Linux-среде разработки; они не заменяют приёмку Windows-приложения по [`acceptance.md`](acceptance.md).

## Выполнено

- `PYTHONPATH=backend python -m unittest discover -s backend/tests -v` — 25 проверок пройдены.
- `python -m compileall -q backend/office_ai backend/tests` — успешно.
- `npm run build` в `frontend` — TypeScript и production-сборка Vite успешны.
- `git diff --check` — ошибок форматирования diff нет.
- Поиск строк, похожих на API-ключи и приватные ключи, в исходниках не нашёл совпадений.
- Проверка файлов репозитория не нашла базы, резервных копий и примеров пользовательских документов.

Проверки backend покрывают каталог агентов, Host/Origin/токен локального API, ограничение методов и CORS, миграции и сохранность настроек, журнал без содержимого, поиск Unicode, форматы документов, размер загрузки, дубликаты SHA-256, безопасные пути скачивания, резервирование, восстановление и требование подтверждать восстановление. Проверка loopback запуска подменяет системный сокет и убеждается, что launcher передаёт `127.0.0.1` в bind и Uvicorn; реальное сетевое соединение в этой среде не открывалось.

## Остаётся проверить на Windows 10 и Windows 11

- Запуск установленного приложения и корректное закрытие окна вместе с локальными процессами.
- Реальную недоступность API с сетевого интерфейса компьютера.
- Отображение русского и казахского текста и навигацию на малом размере окна.
- Импорт и скачивание обезличенных тестовых DOCX/XLSX/PPTX/PDF/JPG/PNG, сравнение размера и SHA-256.
- Системные диалоги сохранения резервной копии и выбора архива восстановления.
- Сохранение данных после перезапуска, восстановление копии и защиту пользовательской директории после обновления/удаления программы.

Установщик ещё не собирался; Windows-сценарии можно завершить после отдельного этапа настройки сборки из [`windows-build.md`](windows-build.md). Поэтому полная приёмка MVP пока не заявляется.
